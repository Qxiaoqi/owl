# Owl PRD

## 1. 产品定位

Owl 是一个运行在 localhost 的技术面试分析工作台。用户上传或粘贴 JD、简历、论文、项目材料和面试记录后，Owl 将这些材料转化为一份围绕 JD 的面试官作战手册，帮助面试官快速理解候选人、识别风险、准备追问，并在面试后完成复盘。

一句话定位：

> Owl 将候选人材料转化为一份基于 JD 的面试官作战手册。

本版本不再走 skill-first 路线。产品入口是一个本地 Next.js Web App。用户期望的使用方式是：

```bash
bun install
bun dev
```

然后在浏览器中完成上传、解析、确认、分析和报告查看。

## 2. 背景

archive 版本已经验证了 Owl 的核心工作流：

1. 解析 JD、简历、论文和面试记录。
2. 将 JD 转成岗位能力模型。
3. 将简历放到 JD 上下文中分析。
4. 用工程面试官能理解的语言解释论文。
5. 生成面试问题树。
6. 根据飞书妙记或面试记录做会后复盘。
7. 渲染一份面试官可直接使用的报告页面。

但 skill 形态不适合承载固定交互。上传文件、检查 PDF 解析结果、确认文本、按步骤分析、查看状态和渲染报告，都是明确的产品 workflow。skill 可以提醒 agent 怎么做，但很难稳定约束用户体验。因此，新版本改为 localhost app。

## 3. 产品目标

1. 提供一个安装简单、启动直接的本地面试分析工具。
2. 继承 archive 版本认可的交互和报告结构。
3. 将原本依赖 skill 约束的流程产品化。
4. 使用纯 Next.js 实现，不引入 FastAPI、Python CLI 或额外后端服务。
5. 让用户能检查和修正 PDF/DOCX 解析结果。
6. 输出一份面试前、面试中、面试后都能使用的报告。

## 4. 非目标

1. 不做 skill 安装器。
2. 不要求用户安装 Python。
3. 不调用 archive 里的 CLI。
4. 不做 FastAPI 服务。
5. 不做 ATS 系统。
6. 不做用户系统和权限系统。
7. 不自动给出 hire/no hire 结论。
8. 不评价年龄、性别、国籍、口音、家庭情况、外貌等岗位无关属性。
9. 不承诺完美还原复杂 PDF 版式。

## 5. 目标用户

| 用户 | 场景 | 核心诉求 |
| --- | --- | --- |
| 技术面试官 | 会前准备 | 快速理解简历、论文、项目和风险点 |
| Hiring Manager | 终面、定级、复盘 | 需要 JD 匹配度、证据和风险判断 |
| Recruiter | 初筛和协调 | 需要候选人亮点、风险点和面试建议 |
| 工程团队负责人 | 同岗多候选人评估 | 希望评估标准围绕同一 JD 保持一致 |

## 6. 核心场景

### 6.1 会前尽调

用户上传 JD 和候选人简历，可选上传论文、项目材料或补充说明。Owl 输出：

- JD 能力模型
- 候选人中文画像
- JD 匹配度
- 简历证据标注
- 风险点
- 面试问题树
- 好答案、弱答案和追问建议

### 6.2 论文候选人评估

面试官不熟悉候选人的论文方向。Owl 将论文转化为工程视角说明：

- 论文解决什么问题
- 方法到底在做什么
- 创新点在哪里
- 实验是否可信
- 局限性是什么
- 和 JD 有什么关系
- 面试应该怎么问

### 6.3 会后复盘

用户粘贴飞书妙记或面试记录。Owl 输出：

- 问答摘要
- 回答质量判断
- 未覆盖问题
- 风险更新
- 二面追问建议
- 面试反馈草稿

## 7. 产品原则

1. **JD 优先**：所有分析围绕当前 JD 展开，避免泛泛总结。
2. **证据优先**：重要判断必须给出来源、引用或不确定性说明。
3. **用户确认文本**：PDF/DOCX 解析结果只是草稿，分析基于用户确认后的文本。
4. **报告优先**：最终产物是一份可执行的面试工作台，而不是聊天记录。
5. **本地优先**：MVP 运行在 localhost，数据保存在本机。
6. **步骤化**：每个分析步骤可见、可重试、可单独修正。

## 8. 核心 Workflow

```text
创建 workspace
  ↓
添加 JD
  ↓
添加候选人
  ↓
上传 / 粘贴简历、论文、面试记录
  ↓
解析文件为文本
  ↓
用户检查并确认文本
  ↓
分析 JD
  ↓
分析简历
  ↓
解释论文（可选）
  ↓
生成面试问题树
  ↓
生成报告
  ↓
添加面试记录并会后复盘（可选）
```

## 10. MVP 范围

### 10.1 MVP 包含

1. Next.js localhost app。
2. 创建和管理本地 workspace。
3. 上传或粘贴 JD。
4. 上传或粘贴简历，支持 PDF、DOCX、TXT、Markdown。
5. 上传或粘贴论文，支持 PDF、TXT、Markdown。
6. 上传或粘贴面试记录。
7. 自动解析材料为文本。
8. 展示解析结果，允许用户编辑和确认。
9. 按步骤执行模型分析。
10. 保存中间 JSON 产物。
11. 渲染报告页面。
12. 支持导出报告 JSON。
13. 支持打印友好的报告视图。

### 10.2 MVP 不包含

1. 团队账户。
2. 云端同步。
3. ATS 集成。
4. 飞书 API 集成。
5. 实时会议转写。
6. OCR 识别扫描 PDF。
7. 复杂表格结构恢复。
8. 多候选人横向对比。

## 11. 功能需求

### 11.1 Workspace

用户可以创建 workspace。一个 workspace 代表一个 JD 和一批候选人。

基础字段：

- workspace 名称
- JD 标题
- 创建时间
- 更新时间

### 11.2 JD 输入

支持：

- 上传 JD 文件
- 粘贴 JD 文本
- 编辑解析后的 JD 文本
- 确认 JD 文本

确认后的 JD 文本是后续所有分析的基础。

### 11.3 候选人材料

每个候选人支持以下材料：

- 简历：必填
- 论文：可选
- 项目材料：可选，可先作为 notes 或补充材料处理
- 面试记录：可选

材料状态：

- uploaded
- parsed
- parse_failed
- confirmed
- stale

### 11.4 解析预览和确认

上传文件后，系统自动解析并展示文本。用户可以：

- 查看解析结果
- 手动编辑文本
- 粘贴替代文本
- 标记为已确认
- 重新解析

如果 PDF 解析为空或质量差，系统提示用户改用 DOCX/TXT/Markdown 或直接粘贴文本。

### 11.5 分析步骤

固定步骤：

1. `analyze_jd`
2. `analyze_resume`
3. `explain_paper`
4. `build_question_tree`
5. `review_interview_notes`
6. `build_report_data`

要求：

- 每一步显示状态。
- 每一步可独立重试。
- 下游步骤依赖的输入变化后，应标记为 stale。
- 模型输出必须经过 schema 校验。

## 12. 分析产物

### 12.1 JD Analysis

输出：

- 岗位标题
- JD 总结
- 必备能力
- 加分能力
- 能力模型
- 面试关注点
- 证据

### 12.2 Resume Analysis

输出：

- 候选人姓名
- 联系方式
- 一句话画像
- 翻译 / 规整后的简历块
- 教育背景
- 工作经历
- 项目经历
- 技能
- 亮点
- 风险
- JD 匹配度
- 证据标注

### 12.3 Paper Analysis

输出：

- 论文标题
- 白话总结
- 研究问题
- 方法解释
- 贡献点
- 实验设计
- 局限性
- 工程解释
- JD 相关性
- 面试追问

### 12.4 Question Tree

输出：

- 问题主题
- 问题正文
- 考察目的
- 关联证据
- 好答案信号
- 弱答案信号
- 追问

问题类型：

- JD 基础确认题
- 简历真实性验证题
- 项目深挖题
- 论文深挖题
- 工程 tradeoff 题
- 风险验证题
- 岗位场景题

### 12.5 Interview Notes Review

输出：

- 问答摘要
- 回答质量
- 已覆盖和未覆盖问题
- 风险更新
- 下一轮追问
- 面试反馈草稿

## 13. 报告需求

报告是核心交付物。

页面结构：

```text
Owl Candidate Report
  ├── Header：候选人、JD、生成时间、状态
  ├── Executive Summary：一句话画像和总体判断
  ├── JD Fit：岗位匹配度
  ├── Resume Review：简历解读和证据标注
  ├── Paper Explainer：论文白话解释
  ├── Risk Board：风险点
  ├── Question Tree：面试问题树
  ├── Notes Review：面试记录复盘
  └── Final Notes：反馈草稿
```

交互要求：

- 顶部或左侧导航。
- 面试问题卡片支持展开 / 收起。
- 问题支持一键复制。
- 风险有等级标识。
- 证据和标注靠近相关判断展示。
- 支持打印视图。

## 14. PDF 解析策略

Owl 不把 PDF 解析结果直接视为真相。系统的真相来源是用户确认后的文本。

策略：

1. 服务端尝试解析 PDF。
2. 展示解析结果。
3. 用户可以编辑或替换。
4. 用户确认后才允许进入分析。
5. 解析失败时，提示上传 DOCX/TXT/Markdown 或粘贴文本。

这个策略允许 MVP 使用纯 Next.js，同时覆盖大部分 JD、简历、论文 PDF 的使用场景。

## 15. 成功标准

1. 用户从安装到生成第一份报告不超过 10 分钟。
2. 用户能在不离开 app 的情况下修正解析问题。
3. 报告能给出具体、可执行的面试问题。
4. 风险判断有证据或明确不确定性说明。
5. 分析结果围绕 JD，而不是泛泛总结候选人。
